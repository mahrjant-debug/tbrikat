# جدارية التهاني والتبريكات

تطبيق ويب عربي (RTL) لحفل زواج جماعي: يعرض تهاني الضيوف على شاشة القاعة مباشرة، ويستقبلها من هواتفهم، ويعتمدها مشرف قبل العرض.

**التقنيات:** React 19 · TypeScript · Vite · Tailwind CSS 4 · motion · canvas-confetti · qrcode · lucide-react · PWA (vite-plugin-pwa) · Firebase (Firestore + Auth). بلا خادم خلفي؛ يُنشر ملفات ثابتة.

## الصفحات

| المسار | الوصف |
| --- | --- |
| `/` | شاشة العرض (تلفاز/شاشة كبيرة). شريط التنقل يظهر عند تحريك الفأرة فقط |
| `/congratulate` | صفحة الضيف (الجوال) |
| `/admin` | لوحة المشرف (تسجيل دخول Firebase Auth) |

## الإعداد

1. أنشئ مشروعاً في [Firebase Console](https://console.firebase.google.com).
2. **Firestore:** أنشئ قاعدة بيانات بالإصدار **Standard** (وضع الإنتاج)، وفعّل خطة **Blaze** (الدفع حسب الاستخدام) — لا تعتمد على الحصة المجانية المحدودة لحفل مباشر — ثم أضف **تنبيه ميزانية** من Google Cloud Billing → Budgets & alerts (مثلاً 5 دولارات).
3. **Authentication:** فعّل مزوّد *Email/Password* وأنشئ حساب **المشرف الرئيسي** من تبويب Users. أبقِ التسجيل الذاتي مفعّلاً: إضافة المشرفين من اللوحة تنشئ حساباتهم عبر التسجيل نفسه.
4. اكتب بريد المشرف الرئيسي في [`firestore.rules`](firestore.rules) (الدالة `ownerEmail`) ثم انشر القواعد:
   ```bash
   npx firebase-tools deploy --only firestore:rules
   ```
   > أنشئ حساب المشرف الرئيسي من Firebase Console **قبل** نشر القواعد، حتى لا يستطيع أحد تسجيل ذلك البريد قبلك. ثم أضف باقي المشرفين من لوحة التحكم (تبويب «المشرفون»).
5. إن كانت قاعدة Firestore **مسمّاة** (وليست `(default)`) فاكتب معرّفها في `VITE_FIREBASE_DATABASE_ID`، وعدّل `database` في `firebase.json` ليطابقها.
6. انسخ `.env.example` إلى `.env.local` واملأ مفاتيح تطبيق الويب (Project settings → Your apps).

```bash
npm install
npm run dev        # تطوير
npm run build      # tsc --noEmit ثم vite build
npm run typecheck  # tsc --noEmit
```

## النشر على Cloudflare Pages

- Build command: `npm run build`
- Build output directory: `dist`
- Environment variables: `NODE_VERSION=22` ومتغيرات `VITE_FIREBASE_*` نفسها من `.env.example`
- أضف نطاق Pages (`xxx.pages.dev` ونطاقك المخصص) في Firebase → Authentication → Settings → **Authorized domains**.
- ملف `public/_headers` يضبط الكاش: `/assets/*` سنة كاملة، و`sw.js` و`index.html` و`manifest` بلا كاش.

## كيف تعمل الدورة

1. الضيف يمسح رمز QR الظاهر على الشاشة ويرسل تهنئته (`/congratulate`).
2. الحالة الابتدائية: كلمة محظورة → `hidden`، اعتماد تلقائي مفعّل ولم يُشترط المشرف → `approved`، وإلا `pending`.
3. المشرف يراجع في `/admin` ويعتمد؛ فتظهر على الشاشة خلال ثوانٍ مع وميض ذهبي وقصاصات ونغمة وبطاقة بارزة 7 ثوانٍ.
   **ترتيب صندوق التهاني من الأحدث إلى الأقدم:** الأحدث اعتماداً هو رقم 1، وكل تهنئة جديدة تأخذ رقم 1 وتنزل البقية رقماً (1 / 101، 2 / 101 ...). تُعرض التهنئة الجديدة فوراً بالاحتفاء الكامل ثم **يتابع الدوران من البطاقة التي كان عندها** نزولاً نحو الأقدم، وبعد آخر بطاقة يلتفّ من رقم 1؛ فلا تُهمَل تهنئة قديمة مهما توالت الجديدة. وإن حُذفت أو أُخفيت البطاقة الظاهرة ينتقل العرض إلى من يأخذ موضعها. الترتيب نفسه يظهر بعد إعادة تحميل الشاشة.

## تصميم البيانات (Firestore)

| المسار | الاستخدام |
| --- | --- |
| `congratulations/{id}` | `name` · `text` · `status` · `createdAt` · `approvedAt?` · `displayDuration?` |
| `settings/global` | الإعدادات العامة (يشترك فيها الضيوف والشاشة) |
| `settings/logo` · `settings/background` | الشعار والخلفية المرفوعان `{dataUrl}` — في وثيقتين مستقلتين حتى لا تثقل إعدادات هواتف الضيوف |
| `photos/{id}` | صور شريط العرسان (JPEG مضغوط < 180KB، `dataUrl`) |
| `partners/{id}` | شركاء النجاح |
| `bannedWords/{id}` | الكلمات المحظورة |
| `videos/{id}` | فيديوهات يوتيوب: `title` · `videoId` (11 حرفاً) · `start` (ثانية البدء) · `scheduleAt` (موعد مستقل، 0 = بلا) · `repeatCount` · `repeatEveryMin` · `repeatUntil` · `enabled` (ظاهر/مخفي) · `order` · `createdAt` |
| `settings/video` | جدولة الفيديو: `enabled` · `intervalMin` · `maxMin` · `triggerAt` · `triggerId` |
| `admins/{البريد بحروف صغيرة}` | المشرفون: `name` · `email` · `role` (`owner` أو `admin`) · `createdAt` · `createdBy?` |

- هواتف الضيوف تشترك في `settings/global` و`bannedWords` فقط ولا تقرأ التهاني.
- الصور مخزّنة كنص Base64 داخل Firestore (لا Firebase Storage) لتبقى الحلول بلا خادم؛ لذلك الضغط التلقائي إلزامي.

## فيديو يوتيوب

- من تبويب **الفيديو** تلصق رابط الفيديو (watch أو youtu.be أو shorts أو live أو embed، ويُحفظ وقت البدء من `t=`). تُفحص صلاحيته عبر oEmbed قبل الحفظ، ويُجلب عنوانه تلقائياً.
- **موعد مستقل لكل فيديو:** عند إضافة الفيديو أو تعديله تحدد تاريخاً ووقتاً (بتوقيت الجهاز)، فيُعرض وحده في موعده ثم تعود الشاشة للتهاني. الفيديوهات ذات الموعد لا تدخل في التناوب التلقائي. لا حدّ لعدد الفيديوهات ولكل واحد موعده.
  - **التكرار:** تحدد «عدد مرات العرض» و«الفاصل بين كل عرض والتالي بالدقائق» (مثلاً 3 مرات كل 10 دقائق = الموعد، ثم +10، ثم +20). لكل عرض مهلة 10 دقائق، وإن حان أكثر من عرض معاً (شاشة كانت مشغولة أو أُعيد فتحها) يُعرض مرة واحدة فقط. لا يتكرر العرض عند إعادة تحميل الصفحة، ويظهر في اللوحة «يُعرض: التالي · N مرات كل M د».
  - يجب أن تكون شاشة العرض مفتوحة في الموعد. إن فُتحت بعده بأقل من 10 دقائق يُعرض فور فتحها، وإلا يُعدّ فائتاً (يظهر «مضى موعده» في اللوحة). لا يتكرر العرض على الجهاز نفسه عند إعادة تحميل الصفحة، وتعديل الموعد يعيد تفعيله.
  - إن حان موعده أثناء فيديو آخر أو تهنئة بارزة ينتظر ثم يُعرض.
- **تكرار الفيديو غير المجدول:** حقلا «عدد مرات العرض» و«الفاصل بالدقائق» متاحان لكل فيديو. كلما جاء دور الفيديو (بالتناوب التلقائي أو بزر ▶) يُعرض ثم يتكرر بقية المرات بعد كل فاصل يُحسب من بداية العرض السابق، وتنتظر التكرارات انشغال الشاشة بتهنئة أو شريك. زر «إيقاف الفيديو الجاري» أو العدّ التنازلي يلغي التكرارات المتبقية، وتُفقد بإعادة تحميل الشاشة لأنها محفوظة في ذاكرتها فقط.
- **تاريخ انتهاء العرض (اختياري):** حقل «ينتهي العرض في» يوقف الفيديو المتكرر بعد ذلك التاريخ والوقت حتى لو لم يكتمل عدد المرات (مثلاً 100 مرة كل 10 دقائق حتى الساعة 10 مساءً). للمجدول: لا تُعرض العروض التي يقع موعدها بعد الانتهاء، وللمتكرر بلا موعد: يخرج من التناوب التلقائي بعده ولا تُجدول تكراراته (يبقى التشغيل اليدوي ممكناً). يجب أن يكون في المستقبل وبعد الموعد الأول.
- **إظهار/إخفاء:** مفتاح عند كل فيديو. المخفي لا يُعرض أبداً (لا تناوب ولا موعد ولا تكرار ولا تشغيل يدوي) وتتعطل أزرار تشغيله حتى يُظهَر، وتبقى بياناته ومواعيده محفوظة. إن أُخفي فيديو أثناء عرضه على الشاشة يتوقف فوراً. وغياب الحقل في الفيديوهات القديمة يُعدّ ظاهراً.
- **مدة المقطع بالثواني:** حقل اختياري لكل فيديو؛ يُعرض هذه المدة فقط من لحظة بدء تشغيله الفعلي ثم تعود الشاشة للتهاني (فارغ = حتى ينتهي). تتقدم على الحد الأقصى العام، وهو الآخر يُحسب الآن من لحظة بدء التشغيل لا من لحظة التحميل.
- **المعاينة:** زر 👁 عند كل فيديو (وفي نموذج الإضافة قبل الحفظ) يفتح مشغّل يوتيوب بأزرار التحكم داخل اللوحة فقط، من وقت البدء المحفوظ، ولا يُرسل شيئاً إلى شاشة العرض.
- **الترتيب:** اسحب مقبض ⠿ عند الفيديو لإعادة الترتيب (يعمل بالماوس واللمس) أو استخدم السهمين؛ يُحفظ عند الإفلات، وهو ترتيب التناوب التلقائي.
- **التشغيل:** يدوياً بزر ▶ عند أي فيديو، أو تلقائياً كل N دقيقة بالتناوب حسب الترتيب، مع حد أقصى للمدة (0 = حتى ينتهي). زر «إيقاف الفيديو الجاري» يعيد الشاشة للتهاني فوراً.
- يُعرض بملء الشاشة عبر مشغّل يوتيوب الرسمي (`youtube-nocookie.com`) دون أزرار تحكم. التهاني الجديدة وشاشة الشريك **تنتظر** حتى ينتهي الفيديو ثم تظهر، أما التسليط التلقائي فيُتجاوز أثناءه. **ويتوقف صندوق التهاني نفسه عن الدوران أثناء الفيديو وشاشة الشريك والتسليط**، ويستأنف بعدها من البطاقة التي توقف عندها (تبدأ مدتها من جديد) فلا تضيع بطاقات خلف الفيديو.
- **الإيقاف من شاشة العرض نفسها:** أثناء الفيديو حرّك المؤشر أو المس الشاشة فيظهر زر «إيقاف الفيديو» أعلى اليسار (يختفي بعد 5 ثوانٍ، ولا يختفي والمؤشر فوقه)، أو اضغط Esc. يعود العرض للتهاني ويُلغي التكرارات المتبقية، ولا يؤثر على شاشات العرض الأخرى (للإيقاف على الكل استخدم زر «إيقاف الفيديو الجاري» في اللوحة).
- **الصوت:** المتصفحات تمنع الصوت التلقائي قبل أي تفاعل؛ اضغط على شاشة العرض مرة قبل الحفل. إن لم يحدث يبدأ الفيديو صامتاً ويظهر زر «اضغط لتفعيل الصوت». زر «كتم الصوت» في الشريط يكتم الفيديو أيضاً.
- **الاعتمادية:** إن انتهى الفيديو، أو حدث خطأ (محذوف، التضمين معطّل)، أو لم يبدأ خلال 20 ثانية (انقطاع إنترنت)، تعود الشاشة للتهاني تلقائياً. الفيديوهات الحية (live) تُقطع عند الحد الأقصى للمدة، فاضبطه لها.
- الشاشة تحتاج إنترنت لتحميل مشغّل يوتيوب؛ لا شيء من الفيديو يُخزَّن في Firestore (الرابط فقط).

## المشرفون المتعددون

- **المشرف الرئيسي** هو البريد المكتوب في `ownerEmail` داخل القواعد: صلاحيته ثابتة ولا تُحذف ولا يُقفل عليه الدخول حتى لو حُذفت وثيقته. تُنشأ وثيقته تلقائياً عند أول دخول.
- من تبويب **المشرفون** يستطيع أي مشرف إضافة مشرف جديد (اسم + بريد + كلمة مرور ≥ 8 أحرف)، وتعديل الأسماء، وحذف المشرفين العاديين. تعديل اسم المشرف الرئيسي وحذفه محصوران في الرئيسي نفسه.
- كل من يُضاف يدخل بحسابه الخاص. الحذف يسحب الصلاحية فوراً (تنتهي قراءته للبيانات وكتابته)، أما حساب Firebase Auth نفسه فيبقى لأن المتصفح لا يملك صلاحية حذف حسابات الغير.
- **كلمات المرور:** يغيّر المشرف كلمة مروره بنفسه من «تغيير كلمة مروري» (تتطلب الحالية). كلمة مرور مشرف آخر لا يمكن تعيينها من المتصفح (قيد في Firebase بلا خادم)؛ لذلك يُرسَل إليه رابط لتعيينها بنفسه، أو يغيّرها هو بعد أول دخول.
- إن أُضيف بريد له حساب سابق يظهر تأكيد صريح قبل منحه الصلاحية، ولا تتغير كلمة مروره.

## ملاحظات أمان

- صفحة المشرف تستخدم ذاكرة Firestore مؤقتة (لا دائمة)، لأن التبويبات في المتصفح نفسه تتشارك اتصالاً واحداً بهوية التبويب الرئيسي؛ فإن كان تبويب العرض (بلا دخول) هو الرئيسي رُفضت طلبات تبويب المشرف. لذلك التنقل بين المشرف وغيره يعيد تحميل الصفحة.

- التسجيل الذاتي عبر واجهة Firebase قد يبقى متاحاً تقنياً لأي شخص يعرف مفتاح الـ API، لكنه لا يمنحه أي صلاحية: القواعد تقصر القراءة الإدارية والكتابة على المشرف الرئيسي ومن لهم وثيقة في `admins`، ولا يستطيع غير المشرف إنشاء وثيقة مشرف لنفسه.
- إنشاء تهنئة من الضيوف مسموح بحقول محددة وأطوال محدودة، والحالة `approved` لا تُقبل إلا حين يكون الاعتماد التلقائي مفعّلاً في الإعدادات.
